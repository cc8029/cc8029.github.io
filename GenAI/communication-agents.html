Building Multi-Channel Communications Agents

So far, we have built agentic workflows involving a single agent. However, more complex tasks often require multiple agents to collaborate. In this section, we will use sub-workflows to orchestrate collaboration among multiple agents.

Sub-workflows also enable us to build custom tools for AI agents. They make our systems more modular by allowing us to reuse components across multiple applications. For example, consider the Google Calendar agent we built in the previous session. We may want to use this agent in several workflows, such as a personal assistant or a workflow that sends event invitations and reminders to multiple recipients. By turning the calendar agent into a sub-workflow, we can invoke it from different workflows instead of duplicating the same logic each time.

To illustrate this, we consider the marketing and communications team at a hypothetical education company, LumaBridge Education, whose mission is to expand access to high-quality bilingual education. The team creates content for multiple channels, including short-form social media posts (e.g., Facebook and X) and long-form articles (e.g., WeChat Official Account). Because the company serves both English- and Chinese-speaking audiences, all social media content should be bilingual. The team hopes to use AI to efficiently create high-quality, engaging content.

Learning Objectives

  • Understanding sub-workflows and calling them both as tools and as parts of our main workflow
  • Building Hierarchical agents
  • Human-in-the-loop

Core Content

The Workflow

Our workflow will

  1. Receive ideas on social media posts and article releases from a form.
  2. Use AI agents to create first drafts based on these details.
  3. Present the drafts to a member of the communications team for review, revision, and final approval.
  4. Translate social media posts to Chinese using an appropriate tone and style.
  5. Send final drafts by email to the communications team for publication.

Sub-workflows

Article releases and social media posts require different formats and styles. Social media posts should capture attention in just a few sentences, whereas article releases are typically more formal and comprehensive. While a single agent could handle both tasks, its performance may suffer in practice when it is overloaded with a wide variety of tasks. Decomposing the workflow into two specialized agents reduces the complexity of each agent and can improve overall reliability. In this example, a single agent would likely be sufficient. However, we split the workflow into separate agents primarily to illustrate an alternative design pattern that you can apply to more complex projects.

In n8n, a sub-workflow is a workflow that is called by another workflow. We use this to create a hierarchical agent structure, where we have one agent that serves simply as a "supervisor" of two other agents, one of which only creates social media posts and the other that only creates article releases. The supervisor agent designates tasks to the social media and article release agents, which then will return posts to the supervisor.

To do this, we start by creating two workflows called Article Release Agent and Social Media Agent. These will be fairly simple workflows. Copy and paste in the following code and explore the two agents.

Within n8n, there are two ways in which we can call these sub-workflows that start with the When Executed by Another Workflow trigger.

  1. Within a workflow using the Execute Sub-workflow node. This is helpful if we have many workflows that have one part of the workflow that is exactly the same. Instead of rebuilding it from scratch, we can just build it once as a separate workflow and then use the Execute Sub-workflow node in each other workflow that needs that process.
  2. As a tool using the Call n8n Workflow Tool. This lets us build custom tools for our agents to use and then call when they deem necessary.

Building the Comms Agent Part 1: First Draft

We now build our main agent, following the steps below.

Step 1: n8n Form

We need a way to start the workflow. In this case, we want team members to be able to give raw information required to create posts. Specifically, we need a post title (for article releases), a post description (containing any relevant details), and the medium (social media post, article release, or both).

  • Add node: n8n Form → On new n8n Form event
    • Add a Form Title (what the form is called)
    • Click Add Form Element
      • Label: Title
      • Element Type: Text Input
    • Click Add Form Element
      • Label: Content
      • Element Type: Text Input
      • Make this a required field
    • Click Add Form Element
      • Label: Format
      • Element Type: Checkboxes
      • Make two checkboxes, Article Release and Social Media Post
      • Limit Selection: Unlimited (since we want users to be able to draft social media posts and article releases simultaneously). You can also use Range of 1 to 2.
      • Make this a required field
    • Click Add Form Element
      • Label: Your name
      • Element Type: Text Input

Alternative: Google Form

We use the n8n Form due to its simplicity. However, it is fairly easy to connect this to a Google Form. To do so, make a Google Form and then under Responses, click Link to Sheets. Now, you have a Google Sheet such that if someone responds to the Google Form, it will appear in the Google Sheet (i.e., a row is appended). We can then use the Google Sheet trigger in n8n to start the workflow.

Remember: for your project, you only need an MVP, and we want you to focus on demonstrating the value of AI rather than on integrating with external services, which might be tricky.

Step 2: First Draft Agent

We will use a hierarchical agent approach to get the first draft of our social media posts/article releases. Specifically, the main agent serves as a supervisor/commander and delegates responsibility to create these posts to the Article Release Agent and the Social Media Agent.

  • Add node: AI Agent

    • Add an appropriate chat model and Simple Memory. For Session ID, choose Define below. We want the model to remember what it has just done for the given execution in case it makes an error and needs to retry, so for the Key, an easy choice would be {{ $json.submittedAt }}. Assuming that no two form submissions are received within the same second, this key will be unique for each submission. As a result, the memory will store only the messages associated with that specific form submission.

    • Prompt:

      Title:  {{ $json.Title }}
Content: {{ $json.Content }}
Format(s): {{ $json.Format }}

    • System Message:

      Act as the in-house marketing and communications specialist for LumaBridge Education, an education company whose mission is to expand access to high-quality bilingual education through programs, digital tools, and live experiences for Chinese- and English-speaking audiences. You have expertise in brand storytelling, public relations, education communications, and multicultural marketing.

Using the content provided, your role is to use your tools to create English-language social media posts and/or article releases (based on the formats) that are both accessible and engaging.

When the format includes social media, use the Social Media tool to write posts. Similarly, use the Article Release tool to write article releases. Do not write these social media posts/article releases yourself; always use the tools to do so.

  • Attach a Structured Output Parser and choose Define using JSON Schema. For the input schema, put

    Code block (10 lines) 
    {
  "type": "object",
  "required": ["social_media_body", "article_release_title", "article_release_body"],

Step 3: Sub-Workflow Calls

Now, article the + for Tools and select Call n8n Workflow Tool. This is how we call a sub-workflow. Choose the Article Release Agent. You should have two Workflow Inputs appear: text and title. Let these be chosen automatically by the model. Now, repeat with the Social Media Agent and its one input of text. This lets our agent now access these workflows as tools and choose the inputs to the workflows.

Building the Comms Agent Part 2: Human-in-the-Loop Edits

We will implement a human-in-the-loop architecture, where our workflow will wait for a member of the communications team to approve the post before sending it on. However, the team member should also be able to suggest edits and iterate on posts before sending them out, as well.
