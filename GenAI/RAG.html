Building a RAG-Powered Q&A Agent

Note that our agent (specifically, the model that it uses) is trained on general data and does not contain by itself specific knowledge about your class or your company. We need to provide our agent relevant internal information to answer domain-specific questions. There are two ways that we can do this: adding information to the system message or giving it access to external files. We currently have focused on adding information to the system message. Now, we focus on letting our agent access information beyond the system message by retrieving it from external files.

Retrieval-Augmented Generation (RAG)

To improve our agent, we want to give it a tool that allows it to search through documents before it creates its response. This is known as Retrieval-Augmented Generation, or RAG. However, it would be extremely inefficient for our agent to have to read through entire documents each time. As a result, we want to consolidate this text into a more accessible format. Specifically, we want the following process:

  1. A user asks a question.
  2. The AI agent searches a knowledge base for the most relevant chunks of text.
  3. These chunks of text are passed to the LLM.
  4. The LLM uses these to compose its response.

In the following, we walk through the workflow that you were given above.

Insert Data to Store (a Simple Vector Store node)

We will build a way to insert the documents into what is known as a vector store. A vector is a string of numbers. We will take our data and transform it into vectors, where similar vectors refer to similar sequences of data.

Note that you might need to make a Memory Key, which is like your key for the Simple Memory subnode.

Default Data Loader

This node decides how to load data into the vector store. Specifically, we need to split the data from the documents into chunks, which are each stored as a separate vector. This node is responsible for determining what type of data is being loaded in and how it is split. Once this is complete, we still need to specify how vectors are created from the chunked data.

Embeddings OpenAI

There are many ways to create vectors from chunked data; it is the process called text embedding. OpenAI provides several embedding models that generate the vectors stored in the vector database. These embeddings capture the semantic meaning of the text, enabling us to retrieve the information most relevant to a query in the next step.

Information Retrieval (a Simple Vector Store node)

The simple vector store, default data loader, and embeddings are what we use to load the data into the vector store. We still need a way to retrieve relevant information from that store so the AI agent can access it.

This node uses the same embedding method to retrieve the stored data most relevant to a given query. From the AI Agent node, connect the + sign where it says Tool to this node. Once connected, the AI agent can reference documents in the vector store.

Preparing RAG Input

We will add documents to the vector store through file submissions via a form.

  • Add node: Add another trigger → On form submission

    • Form Title: Something like "Upload Files to Your RAG Knowledge Base."
    • Click Add Form Element. Choose Element Type: File.

  • Connect the output of this node to the Insert Data to Store node.

  • What it does: The On form submission trigger starts the workflow when a user submits a form. In our specific case, when we fill out the form and submit a file, the workflow then embeds the data from the file as vectors, which can be retrieved later.
