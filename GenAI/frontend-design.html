Building End-to-End Products with AI

So far, we have focused on n8n’s core functionality and on building workflows within its interface. In this session, we will connect n8n to Lovable to add a frontend, turning our workflows into a complete, end-to-end product.

Learning Objectives

  • Explain what a webhook is and how webhooks work in n8n.
  • Describe how to connect n8n to a front-end tool such as Lovable (or another app that can send HTTP requests).

HTTP Requests and Webhooks

An HTTP request let you send information from n8n to other services. While you might receive information back, this interaction is initiated by n8n. Many of the nodes we have already used (such as adding rows to a Google Sheet or calling the OpenAI API) are HTTP requests that have a nice wrapper to make them easier to use.

A webhook lets you receive information from other services. This interaction is initiated by an external service, not n8n. For example, some trigger nodes (like triggering a workflow when we receive an email) would be a webhook. In our case, a message submitted through a webpage will trigger the workflow.

Both HTTP requests and webhooks support many methods for sending and receiving different types of information. These methods are beyond the scope of this course, but you can learn more about them here.

In n8n, a Webhook node has the following components:

  • A method (GET, POST, etc.).

    • The method defines the purpose of the request and the expected behavior. In our case, we will use POST to exchange information between the frontend and n8n.

  • A path (e.g., "39706c09-...").

    • This value is randomly generated and forms the final part of the webhook URL.

  • A derived URL in the following format:

    https://<your-n8n-instance>/webhook/<path>

n8n provides both a test URL and a production URL. The production URL is the one you will use in your deployed application. Whenever a request is sent to this URL, the workflow starts running from that Webhook node.

We will choose the Respond option called Using 'Respond to Webhook' node, which gives you more control over when and how the workflow returns a response.

Important for security:

Never publish your real webhook URLs. Anyone with access to a webhook URL can send data to it, potentially exposing sensitive information from your workflows.

Part 1: ChatGPT Clone

As a simple example, we will build something like a chatbot, with a frontend in Lovable and a backend in n8n. Let's get started!

Step 1: Webhook

  • Add node: Webhook

    • This lets us receive information sent from Lovable. The Test URL or Production URL (depending on which one you choose) indicates where Lovable will send information that n8n will then listen for.

    • HTTP Method: Choose POST. This is the most common method we will use, since it is the standard way to send data from one system to another.

    • Path: We can leave this, but we can also change it. Note that it changes the URL as well.

    • Authentication: We will leave this as None, but we can use this to verify that the service calling the webhook is one that we recognize.

    • Respond: We need our AI Agent to first create a response, so we choose Using 'Respond to Webhook' Node.

    • You can look at the options for how to deal with sending files (binary data), among other things.

  • What it does: This lets us receive messages from Lovable.

For now, we use the Test URL, but we would switch this to Production URL for deployment.

Step 2: AI Agent

When Lovable sends information to our n8n webhook, it uses JSON format. In this example, we assume that Lovable sends a JSON object called body with keys text (representing the message from the user) and sessionId (representing the conversation ID).

As before, we want to make sure that our agent remembers our conversation. We will do this by having Lovable generate a sessionId every time that a user visits the website and then we will pass this back and forth between Lovable and n8n, using it to remember which messages to reference.

  • Add node: AI Agent

    • Source for Prompt: Choose Define below.

    • Prompt (User Message): Use the following. In our Lovable prompt, we will specify how information will be sent from Lovable.

      {{ $json.body.text }}

    • We can always add a system prompt or some tools!

  • Add a Chat Model and Simple Memory. In Simple Memory:

    • Session ID: Choose Define below

    • Key:

      {{ $json.body.sessionId }}

Step 3: Webhook Response

By default, the AI Agent node returns a single key, called output. We then want to send that back to Lovable, along with the sessionId so that we can continue to pass it back and forth.

  • Add node: Respond to Webhook

    • Respond With: Choose JSON

    • Response Body:

      {
  "output": {{ JSON.stringify($json.output) }},  
  "sessionId": "{{ $('Webhook').item.json.body.sessionId }}"  
}

Note that we need to put JSON expressions in quotations to signal that they are strings.

Now, we are pretty much set in n8n! If we want to have this workflow constantly listen for anything from Lovable, we need to publish the workflow.

Step 4: Lovable

Now, we need to set up our front end! You can do this in many ways, but the important information is that we are making a chatbot with an n8n back end and that we have certain JSON keys that we will send/receive, along with the method that we will use. Here is the prompt that I used, but feel free to come up with your own:

Create a ChatGPT-style AI chatbot using n8n as a backend. The chatbot should use the POST method to the URL https://genai-business-chen.app.n8n.cloud/webhook-test/69202c9e-ad2c-4e9e-8cfd-15a86aeb53ef and send a JSON object with keys `text` (which is the user message) and `sessionld` (a unique session ID for this conversation). Generate a new `sessionId` every time a new user visits the site. You will receive back a JSON object with keys `output` (the assistant's response) and `sessionld` to keep track of the conversation. You will display output. Make this chatbot NYU purple.

Note that I didn’t even tell it how to handle sessionId. We might want to specify this, just to make sure that it is doing what we want, but it is a good starting point!

Exercises:

  1. What would we do if we want our chatbot to be able to read our email? Note: this is sort of like how different services connect to ChatGPT, Claude, or other LLMs!
  2. What if we want the user to be able to set a system message?

Part 2: Interview Prep Agent

Our running example is an interview coach bot. Our process will be as follows:

  1. A user completes a form on a website with the following information:

    • Interviewee name
    • Company name
    • Job title
    • Job description
    • (Optional) Resume upload

  2. When they submit the form, an AI agent acts as the interviewer, asking questions based on the job description. Questions and answers will be logged in a Google Sheet for future reference.

  3. At the end, the user can click “Analyze conversation”:

    • n8n pulls the full conversation from the Google Sheet.
    • This is sent to an Analysis Agent, which returns feedback on their performance.

Note that while we could do this all in n8n, most products have a nice frontend. We will make a website in Lovable and then use a webhook to send information back and forth between Lovable and n8n.

We will log each interview question and answer in a Google Sheet with the following columns:

This workflow consists of three parts:

  • The user form and initial question;
  • The interview, including both questions and answers;
  • The analysis of the conversation.

Because these are three separate processes, we use a dedicated webhook for each.

Here are a few highlights for you to explore:

  • The Extract from File node lets you extract text or other information from a document. In our case, this lets us extract the raw text from a resume/CV for our AI agent.
  • We enable web search in the OpenAI Chat Model. This gives the agent the ability to gain additional context on the company.
  • For each subsequent interview response, we do not include the entire conversation history in the Prompt (User Message) field. Instead, we create a session ID at the beginning of the interview and use it together with the Simple Memory node to keep track of the conversation history.
  • In the analysis section, we use a Code node called "Recreating Transcript" to convert the rows in the Google Sheet into a transcript of the conversation.

Important for security:

If you copy the workflow above, delete and recreate the Webhook node to generate a new webhook URL. The original URL has been published online and should no longer be considered secure.

Create a single-page web app with three main screens:

1. **Intake Form**
2. **Interview Chatbot**

The app should move through these screens in order:


Only one main screen should be visible at a time.

## Important Backend Behavior

This app uses n8n webhooks.

For each backend action, call **both provided webhook URLs** in parallel. Treat the request as successful if at least one webhook returns a valid response containing the expected `output` field.

Use the first successful response that contains the expected `output` field.

If both requests fail, or if neither response contains the expected field, display a user-friendly error message and allow the user to retry.

Do not use mock responses.
